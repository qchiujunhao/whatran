# Recorded demo — the whole flow

A synthetic "LC-MS-like" analysis taken through every everyday command:
`run` (what the Claude Code hooks do automatically), `record "what it did"`,
`reject`, `claim`, `done`, `package`, `check`. Everything here is generated by
`make_demo.sh`; nothing is hand-written except the three scripts.

The analysis: simulate 12 samples with three planted features, detect peaks on
the mean spectrum, compare groups with a Welch t-test, and claim two findings.
One peak-detection attempt (threshold 1.1) called dozens of noise bins as peaks
and was rejected; it stays in the record. `package` wrote `whatran.json`,
`run.sh` (the three recorded commands), `check.py`, `build_site.py` and the CI
workflow; `check` reran them from clean, compared, and marked the three steps
replay-verified.

```bash
bash make_demo.sh                      # rebuilds everything from scratch
python3 analysis/whatran.py open       # the graph
python3 build_site.py && open site/index.html   # the result page
```

What to look at in the viewer:

- the default view shows only the result path (4 runs, 5 files, 2 claims);
- **Show explored branches** reveals the rejected run and its output, dashed;
- **Execution log** lists all five captured commands, including the debugging
  one that no node links to;
- click any run for its command, parameters, code hash, inputs and outputs, and
  the evidence block: every run here is `observed` because each step went
  through `whatran.py run`, and the three on the result path are
  `replay verified` because `check` reran them and the outputs matched. The
  rejected run is observed but not replayed: it is not part of the package.
